# Feature: Security & Hardening (SSOT)

## Contexto
Esta feature centraliza as decisões e mecanismos de segurança do Treq Enterprise, focando em isolamento de dados (RLS), autenticação JWT e conformidade LGPD.

## Arquitetura de Segurança
1. **SSOT (Single Source of Truth)**: Todas as configurações estão em `backend/app/config.py`. Nenhuma variável de ambiente deve ser lida fora deste arquivo usando `os.getenv`.
2. **Autenticação**: Baseada em OAuth2 com Bearer Tokens (JWT).
   - Segredo: `JWT_SECRET_KEY` (mínimo 32 bytes).
   - Algoritmo: HS256.
   - Flow: `/auth/login` gera o token; `get_current_user` valida o token e extrai o `user_id`.
3. **Isolamento de Dados (Native RLS)**:
   - O `RAGService` e as ferramentas do Agente recebem um `user_id`.
   - Utilizamos `get_user_supabase_client(user_id)` para criar um cliente Supabase autenticado que respeita as políticas de RLS do banco de dados.
   - **IMPORTANTE**: O `supabase_service_role_key` (Admin) só deve ser utilizado para operações de manutenção ou bypass explícito de RLS devidamente documentado.

## Endpoints Protegidos
Todos os endpoints em `/agent`, `/chat`, `/audio` e `/documents` exigem o header `Authorization: Bearer <token>`. O backend valida o JWT e extrai o `id` do usuário para aplicação de RLS.

## Frontend Auth Flow
1. **Login Page**: Localizada em `/login`, utiliza `react-hook-form` + `zod` para coletar credenciais e obter o JWT.
2. **Token Management**: O token é persistido no `localStorage` sob a chave `treq_token`.
3. **API Integration**: Todos os hooks (`useChat`, `useDocumentUpload`, etc.) injetam o token automaticamente no header das requisições.
4. **Auth Guards**: Rotas `/chat` e `/agent` verificam a presença do token no `useEffect` e redirecionam para `/login` se ausente.
5. **401 Resilience**: Caso o backend retorne 401 (token expirado ou inválido), o frontend limpa o `localStorage` e redireciona o usuário para o login com uma mensagem de erro.

## Local Testing (E2E)
- Os testes em `frontend/e2e/agent.spec.ts` simulam o login real e injetam o token no `localStorage`.
- O backend deve estar rodando com as credenciais sincronizadas no `.env` da raiz.

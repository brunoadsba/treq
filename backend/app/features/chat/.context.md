# Contexto da Feature: Chat Backend

## Arquitetura
O backend do chat é modularizado para suportar diferentes estratégias de processamento (RAG, Tools, Direct).

## Regras de Processamento

### 1. Sistema de Níveis de Alerta
- Toda resposta classificada como Alerta/Contenção deve obrigatoriamente seguir o padrão de nomenclatura:
  - **Nível 1: Atenção** (Amarelo)
  - **Nível 2: Crítico** (Vermelho)
- O início da resposta deve ser mandatório com a sentença: `**Status Operacional: [Nível e Cor]**`.

### 2. Nacionalização e Acessibilidade
- Termos técnicos em inglês ou jargões são proibidos na resposta final para o usuário.
- Mapeamento mandatório nos prompts:
  - SLA -> Prazo
  - Threshold -> Limite / Gatilho
  - KPI -> Indicador de Performance
  - Playbook -> Manual de Procedimentos

### 3. Integridade de Dados e Clean-RAG
- **Clean-RAG**: Filtro automático que ignora fragmentos biográficos (currículos, bio) em queries do tipo `procedimento`, `alerta`, `status` ou `geral` (a menos que a query mencione nomes próprios).
- **Classificação**: Suporte a queries plurais ("Quais são os procedimentos") e combinações verbais complexas para garantir o acionamento do roteamento correto.
- Valores numéricos de métricas devem ser extraídos literalmente. É proibido arredondar valores como `38.5` para `39`.
- Se o contexto mencionar gatilhos e a métrica atual, a comparação deve ser explícita na resposta.

## Prompts Principais
- `alerta.yaml`: Gerencia protocolos de contenção.
- `metrica.yaml`: Gerencia extração decimal e comparação.
- `default.yaml`: Base do sistema, evita alucinações e vaza de instruções.

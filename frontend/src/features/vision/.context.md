# Contexto: Feature Vision

## Decisões Arquiteturais e Conectividade

### 1. Variável de Ambiente: `NEXT_PUBLIC_API_URL`
Foi implementado o uso da variável `NEXT_PUBLIC_API_URL` no frontend para centralizar a comunicação com o backend.

**Significado:**
- **Ponto Único de Configuração:** Define o endereço (URL + Porta) onde o Backend do Treq está rodando.
- **Porta 8002:** Durante o desenvolvimento da feature Vision, o backend foi configurado para a porta **8002** para evitar conflitos e garantir estabilidade nos testes de hardware (Câmera).
- **Segurança (Next.js):** O prefixo `NEXT_PUBLIC_` é obrigatório para que o navegador (Client-side) consiga acessar essa variável. Sem isso, os hooks de upload (`useDocumentUpload`) não conseguem enviar fotos capturadas.

**Transição para Produção:**
Para publicar o sistema, basta alterar o valor no arquivo `.env` ou nas configurações do servidor (Vercel/Supabase):
```env
# Exemplo de Produção
NEXT_PUBLIC_API_URL=https://api.treq.com.br
```

### 2. Interface de Captura (UX)
- **React Portals:** O modal da câmera utiliza `createPortal` para garantir que os controles (Z-Index) fiquem acima de qualquer elemento da UI, evitando cortes por `overflow`.
- **Hardware Fallback:** O sistema tenta primeiro a câmera traseira (`environment`) e faz fallback automático para qualquer câmera disponível caso falhe.

### 3. Integração Multimodal
- As capturas são enviadas para o endpoint `/documents/upload` (ou `/upload-multimodal`) e processadas pelo Gemini 1.5 Pro no backend para extração de tabelas e geração de relatórios CoT.
